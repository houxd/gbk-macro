# gbk-macro

编译期将 UTF-8 字符串字面量转换为 GBK / GB2312 字节数组的过程宏（proc-macro），面向嵌入式 `no_std` 目标。

源码与编辑器使用 UTF-8，但许多单片机外设（串口屏、热敏打印机等）只接受 GB2312 / GBK 编码。本 crate 在**编译期**完成转码，生成普通的 `&[u8]` 常量：

- 目标固件中不包含转码表；
- 运行时没有任何编码转换开销；
- 展开结果不依赖任何运行时库，可直接用于 `no_std` 项目。

过程宏本身在宿主机上执行，依赖的 `encoding_rs`、`syn`、`quote` 等库仅在编译时使用，不会进入最终固件。

## 功能

| 宏 | 编码 | 说明 |
| --- | --- | --- |
| `gbk!("...")` | GBK | 将字符串编码为 GBK 字节数组。无法表示的字符（如 emoji）编译报错。 |
| `gb2312!("...")` | GB2312（EUC-CN） | 在 GBK 编码基础上额外检查：若结果包含 GB2312 之外的汉字（如部分生僻字、GBK 扩展字符），编译报错。 |

补充说明：

- ASCII 字符原样保留（单字节直通）。
- 支持字符串中的 Rust 转义序列，例如 `\u{7CFB}`。
- 输入必须是字符串字面量，不支持变量或表达式。
- 出错时，编译器会指出具体的字符（或双字节编码）及其 Unicode 码位，便于定位问题。

## 安装

在 `Cargo.toml` 中添加依赖：

```toml
[dependencies]
gbk-macro = "0.0.1"
```

## 使用方法

```rust
#![no_std]

use gbk_macro::{gb2312, gbk};

// 编译期生成 &'static [u8]，可用于 const 上下文
const MSG_START: &[u8] = gbk!("系统启动中...");
const MSG_ERROR: &[u8] = gb2312!("传感器异常！");

fn report() {
    // 直接交给串口 / 串口屏驱动发送字节
    // uart.write(MSG_START);
    // uart.write(MSG_ERROR);
}
```

展开后的结果等价于字节数组字面量。例如：

```rust
const MSG_START: &[u8] = gbk!("系统启动中...");
// 等价于
const MSG_START: &[u8] = &[0xCF, 0xB5, 0xCD, 0xB3, 0xC6, 0xF4, 0xB6, 0xAF, 0xD6, 0xD0, b'.', b'.', b'.'];
```

### 何时选择 `gb2312!` 还是 `gbk!`

- 如果设备只支持 GB2312（很多老式串口屏、字库只含一级/二级汉字的设备），使用 `gb2312!`，可在编译期发现会显示为乱码的字符。
- 如果设备字库支持 GBK，或需要使用 GB2312 之外的生僻字，使用 `gbk!`。

对于常用汉字，两者的输出完全相同。

### 编译期错误示例

```rust
const A: &[u8] = gbk!("😀");        // 错误：字符 '😀' (U+1F600) 无法编码为 GBK
const B: &[u8] = gb2312!("镕");     // 错误：字符串可编码为 GBK，但不属于 GB2312
```

## 运行测试

```sh
cargo test
```

测试覆盖：ASCII 直通、空字符串、示例文本编码、Unicode 转义、中英文混排、`gb2312!` 与 `gbk!` 的一致性，以及 emoji 与 GBK 独有字符的错误检测。

## 注意事项

- 转换在编译期进行，因此字符串必须是字面量。
- GB2312 的判断基于标准规定的汉字区（首字节 `0xA1–0xF7`，次字节 `0xA1–0xFE`，并排除 `0xAA–0xAF` 空闲区），与 GBK 的完整编码表不同。
- 本 crate 仅做编码转换，不负责串口/屏幕驱动及字库本身的支持范围，请确认目标设备字库覆盖所用字符。
